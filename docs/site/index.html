Book demand-response trips across providers, with an API you can test

A machine-readable binding of the Transactional Data Specification (TDS, TCRP Report 210, 2020): OpenAPI 3.1 for booking calls, AsyncAPI 3.0 for webhook events, JSON Schema for the data, plus a conformance kit and a reference mock. It is not a new standard; it makes TDS implementable and testable.

Reference documentation

Trips API

Requester to provider calls: request, confirm, modify, cancel and read trips; webhook subscriptions; transfer-profile tenders and holds; health and capabilities.

openapi.yaml

Events

Signed webhooks a provider sends for every change: trip status, milestones, ETA bands, custody hand-offs and exceptions. Standard Webhooks signatures, optional CloudEvents headers.

asyncapi.yaml

Relay mailbox

An HTTPS mailbox, served by the requester, that moves CSV trip files for providers whose scheduler can only call out (behind a firewall, or in a spreadsheet platform).

relay-mailbox.yaml

Who it's for

Transit agencies

Guidance for agencies

Scheduling vendors (providers)

Implement the Trips API and events, then point tds-conform at your endpoint to check it at the Core, Transfer, Paratransit or NEMT level.

Test your endpoint

Brokers and coordinator tools

Build against tds-mock, a stateful set of reference providers with signed webhooks and a simulated clock, before you have a live partner.

Run the demo providers

Profiles

Rider data is minimal by design: accessibility needs are service requirements (such as WHEELCHAIR_LIFT), never health conditions.

Try it locally

Needs uv (Python 3.12) and Node 20+.

git clone https://github.com/kovirlabs/tds-openapi && cd tds-openapi
npm install && npm run bundle
uv run tds-mock --demo                 # reference providers on :4010
uv run tds-demo run                    # narrated transfer scenarios
uv run tds-conform run --url http://localhost:4010 --profile transfer

Status

Draft. Field names are proposed and are being checked against TDS 2020 in the crosswalk; vocabulary is borrowed from GTFS, GTFS-Flex, NeTEx and EDI 214 where it fits. Read SPEC.md for scope and design, and the changelog for what changed. The project is intended for donation to a neutral steward.
